# SkySense++ L20 部署文档 v1

> 适用版本：skysense-pp-l20-port（基于上游 kang-wu/SkySensePlusPlus @ cb0c6b7）
> 部署目标：NVIDIA L20（Ada / sm_89）+ PyTorch 2.1.2 + CUDA 12.1 容器
> 验证场景：flood3i 1-shot 语义分割（4919 batch 全量，mIoU 0.5513）

---

## 一、部署架构与拓扑

本部署面向浪潮云 GPU 环境（K8s 集群 + 跳板机中转），链路如下：

```
跳板机 JUMP  ──SSH 中转──▶  gpu-0002（内网 IP，NVIDIA L20）
<跳板机 IP>:<SSH 端口>              │
                                    ├─ hostPath: /root/SkySensePlusPlus（代码+数据挂载点）
                                    └─ K8s Pod（nodeSelector=gpu-0002，申请 1 张 L20）
```

> 说明：上图中的跳板机 IP、SSH 端口、gpu-0002 内网 IP 属内部环境信息，按安全规范以占位符表示，部署时替换为实际值即可。

部署介质经跳板机落地后，通过 K8s Pod 调度到 gpu-0002 执行容器内安装与推理。

## 三、环境准备

### 3.1 基础镜像

```bash
docker pull pytorch/pytorch:2.1.2-cuda12.1-cudnn8-devel
```

镜像预装 torch==2.1.2+cu121、torchvision==0.16.2，无需重装 CUDA 工具链。

### 3.2 依赖安装（容器内，由 start_1shot.sh 自动执行）

关键点：

- **不要使用上游 requirements.txt**（pin 了 torch==1.13 + cu117，无法在 L20 运行）；
- 使用 `scripts/requirements_l20.txt`：mmcv==2.1.0 / mmsegmentation==1.2.2 / mmengine，mmcv 走 openmmlab cu121-torch2.1 预编译 wheel（--find-links），避免 nvcc 源码编译；
- pip 源使用阿里云（`https://mirrors.aliyun.com/pypi/simple/`），实测 gpu-0002 上清华源超时、阿里云 4.5MB/s；
- antmmf 无 setup.py，不执行 pip install -e，靠 `PYTHONPATH` 引用（run_1shot.sh 内建）；
- opencv 切换为 opencv-python-headless；
- flash-attn 不预装（标准 attention 可绕过，省 nvcc 编译）。

## 四、代码与数据放置

```bash
# gpu-0002 宿主机挂载点（K8s hostPath）
mkdir -p /root/SkySensePlusPlus

# 从上游克隆完整项目
git clone https://github.com/kang-wu/SkySensePlusPlus.git /root/SkySensePlusPlus

# 应用适配补丁（介质内）
cd /root/SkySensePlusPlus
git apply /path/to/patches/skysense_pp_l20_port.patch
```

数据放置（与上游 README 一致，路径以实际为准）：

| 数据 | 路径 |
| --- | --- |
| flood3i 影像与标注 | `eval_datasets/flood3i/` |
| 模型权重 ckpt | `save/`（或配置指定的 ckpt 路径） |
| 推理输出 | `eval/flood3i_1shot/save/`（自动生成） |

## 五、1-shot 推理运行

```bash
# 容器内执行（hostPath 挂载为 /workspace）
bash /workspace/start_1shot.sh
```

脚本流程：

1. 环境检查（python3 / torch / CUDA 设备名，应输出 NVIDIA L20）；
2. 依赖安装（requirements_l20.txt + antmmf PYTHONPATH + opencv-headless 等）；
3. 清理 `__pycache__` 并注入 mmcls `get_root_logger` 兼容补丁；
4. 执行 `tools/run_1shot.sh`（0-shot prompt 采样 + 4919 batch 全量推理）；
5. 输出 pred 图至 `eval/flood3i_1shot/save/`，`vis_full/` 子目录为 input+pred+gt 三联图；
6. 最终评估 `lib/evaluation/segm_eval_base.py` 打印逐类 IoU 与 Mean mIoU。

单次推理约 1 小时（4919 batch，1.28 it/s）。

## 六、结果验证

预期指标（flood3i 1-shot 全量）：

| 指标 | 期望值 |
| --- | --- |
| Mean mIoU | 0.5513（基准 0.5515） |
| Mean Acc | 0.7871 |
| 类别 1（建筑）IoU | 0.8098 |
| 类别 8 IoU | 0.2380（最低类，与基准一致） |

判定要点：

- 若 mIoU 接近 0.55 量级 → 部署成功；
- 若 mIoU 接近 0.01（pred 全黑，文件 < 1KB）→ 命中 Proj_MHSA 残差缺陷，按第八章回滚检查。

## 七、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'transformers'` | 依赖未安装完整 | 确认 start_1shot.sh 依赖段执行完成 |
| pred 全黑（文件 ~842B） | Proj_MHSA 丢失 identity 残差 | 检查 swin_v2.py 是否有 `x = x + identity` |
| mmcv 安装编译失败 | 走源码 nvcc 编译 | 确认 --find-links openmmlab cu121/torch2.1 wheel 索引 |
| pip 下载超时/卡死 | 源不可达 | 切换阿里云源（脚本已内置） |
| `get_root_logger` 报错 | mmcls/mmengine 版本兼容 | 按 start_1shot.sh 注入兼容补丁 |
| CUDA OOM | 申请 GPU 资源不足 | Pod resources 声明 `nvidia.com/gpu: 1` |

## 八、回滚

## 九、已知问题

1. 本适配仅验证 flood3i 1-shot 推理链路；训练链路（MIM 预训练）未在 L20 上验证；
2. `replace_speedup_op: False` 关闭 atorch 加速算子，推理速度依赖 torch SDPA（内存高效路径）；
3. torch 原生 MHA 与 mmcv 包装类的数值差异已通过补回残差消除，但未做逐层输出 bit 级对齐；
4. 升级 torch 2.2+ 时 `torch.nn.attention.sdpa_kernel` API 变化，需同步适配。
